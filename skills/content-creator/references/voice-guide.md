# Deriving and enforcing a brand voice

Read this when building a voice guide for the first time, revising one, or running the
check on a draft. The short form lives in `SKILL.md`; this is the procedure.

## 1. Analyze the samples

Start from **three to five pieces the owner is happy to be judged by**. Never invent a
voice from nothing. With no samples, the first job is to get one page written or approved.

Record observations, not impressions. "Confident" is an impression; "no hedging verbs in
any of the five samples" is an observation.

| Dimension              | What to record                                                                                |
| ---------------------- | --------------------------------------------------------------------------------------------- |
| **Sentence length**    | Typical range and the longest tolerated. Count, do not estimate.                              |
| **Person and address** | we / I / the company; you / they / the reader. What the samples _do_.                         |
| **Vocabulary level**   | Does it explain jargon, assume it, or avoid it? Terms that recur, terms conspicuously absent. |
| **Claim style**        | Hedged ("often", "can help") or committed ("does", "will")? Where numbers appear.             |
| **Structure**          | How it opens, headings and lists, paragraph length, how it closes.                            |
| **Humor and warmth**   | Present or absent, and in what register — as observed, never as aspiration.                   |

## 2. Write the rules

At most **twelve**. A guide nobody can hold in their head is a guide nobody applies.

Each rule is stated so a draft can be checked against it without a judgement call, and
carries a real example and a counter-example in the samples' register:

```text
RULE: Lead with the reader's problem, not the company.
YES: "Invoices pile up when three people share one inbox."
NO:  "We are excited to announce our new invoicing workflow."
```

Split them into three sections:

- **always** — do this every time
- **never** — banned constructions, words, and claims
- **it depends** — with the deciding condition stated, so it is still checkable

A rule with no counter-example is usually an impression that has not finished becoming a
rule. Write the counter-example or drop it.

## 3. Run the check

Every draft clears this **before** submission, not after review. Run it as a table:

| Rule | Pass/fail | Offending line | Rewrite |
| ---- | --------- | -------------- | ------- |

Four rules govern the check:

1. **Any _never_ hit is a fail.** No exceptions, no averaging against the rest of the
   draft.
2. **Fails are returned with the rewrite attached.** A finding without a proposed line is
   unfinished.
3. **A clean pass says what was checked** and names the two or three rules that came
   closest to failing. A silent approval is indistinguishable from a skipped check.
4. **A rule that keeps failing across drafts is the rule's problem, not the writer's.**
   Flag it for re-derivation against the samples.

## 4. Maintain it

Keep the guide where the next session can retrieve it, and **re-derive it whenever the
owner approves writing that breaks a rule**. The samples are the authority; the guide is a
compression of them, and an approved sample that contradicts a rule is evidence the
compression was wrong.

The guide is working when two different drafts of the same brief are recognizably the same
company, and when every rule change traces to an approved sample that broke it.
